# UN1CA A52s 5G — One UI 6.1.1 Performance/Autonomy fork

This fork is based on **UN1CA 2.5.6**, the One UI 6.1.1 line for the Galaxy A52s 5G (`a52sxq`). It keeps the upstream device configuration and adds a small device-specific tuning layer.

## Changes

- **Conservative debloat:** removes optional Samsung components that are not required for telephony, camera, biometrics, NFC, or the Always On Display: Smart Tutor, Game Home, Samsung Car Key firmware, OneDrive, and Upday. Qualcomm radio, camera, fingerprint, and core Samsung services are intentionally retained.
- **Native fullscreen AOD capability:** exposes `SEC_FLOATING_FEATURE_LCD_CONFIG_AOD_FULLSCREEN=1` in the stock Samsung floating-feature set. This enables the native One UI 6.1 setting; it does not replace the AOD application or force an unsupported refresh mode.
- **Adaptive refresh and idle timers:** keeps content-aware refresh enabled and applies conservative SurfaceFlinger idle/touch/display timers. Thermal management and charging protections are not disabled.
- **Autonomy-oriented scheduling:** preserves the existing A52s cpuset tuning, keeping background work on efficiency cores and restricting background groups without changing foreground CPU policy.

## Build

Use the upstream build prerequisites and supply firmware for the target A52s bootloader. The device requirement remains an **Android 14 bootloader**. From the repository root:

```bash
source buildenv.sh
./build.sh a52sxq
```

The exact build entry point may vary with the upstream checkout; consult the upstream README and `buildenv.sh` before starting a release build. This fork does not bundle Samsung firmware or proprietary blobs.

## Validation checklist

Before publishing a flashable artifact, validate the generated package on a spare/test device:

1. Confirm the device is `SM-A528B`/`a52sxq` and the bootloader is compatible with Android 14.
2. Make a complete backup of user data and the original firmware.
3. Verify mobile network, Wi-Fi, Bluetooth, NFC, cameras, fingerprint, charging, sleep/wake, and AOD.
4. Open **Settings → Lock screen and AOD → Always On Display** and verify the fullscreen wallpaper option is available.
5. Monitor idle drain and thermal behavior for at least one full charge cycle.
6. If a removed optional app is needed, restore the corresponding entry in `target/a52sxq/debloat.sh` and rebuild.

This is an experimental community ROM modification. Flashing custom firmware can trip Knox, erase data, or leave the device unbootable if the wrong firmware is used. No claim of battery-life improvement is made without device-specific measurements.
